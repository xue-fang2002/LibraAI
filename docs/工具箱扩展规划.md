## 3. 新增依赖评估

| 依赖 | 用途 | 安装成本 | 建议 |
| --- | --- | --- | --- |
| `pdfplumber` | PDF 表格提取 / PDF 对比 | 低（纯 Python + pdfminer.six） | 加，写进可选区 |
| `zhconv` | 简繁转换 | 极低（单文件） | 加 |
| `pypinyin` | 拼音 | 低（自带词库） | 加 |
| `markdown` | MD → HTML/DOCX | 低 | 加 |
| `python-barcode` | 条形码 | 低 | 加 |
| `reportlab` | 生成 PDF / 复杂水印 | 低（纯 Python） | **尽量不加**，PyMuPDF 已能画水印/页码 |
| `pillow-heif` | HEIC | 低 | P3 |
| `cairosvg` | SVG 转图 | **中（Windows 需 GTK）** | P3，谨慎 |
| `ffmpeg` | 音视频 | **高（外部二进制）** | 不入 requirements，走运行时探测 |
| `calibre` / `7-Zip` | 电子书 / rar | 高（外部程序） | 不入，运行时探测 + 友好提示 |

**统一约定（重要）**：所有新工具在 `run()` 内部 `import`，失败返回 `fail("需安装 xxx：pip install xxx", code=503)`。工具箱 registry 已经保证「单个工具导入失败不影响其它工具」，这条机制必须沿用。

## 7. 明确不做清单（避免后续反复讨论）

| 不做 | 原因 |
| --- | --- |
| PDF-A 转换 | PyMuPDF 做不到真正合规，属虚假功能 |
| 真密码破解 | 技术不可能 |
| PDF 在线阅读器 | 前端范畴，清单已排除 |
| EPUB/MOBI/AZW3 电子书 | 需 calibre，离线环境无需求 |
| AI 图像修复 / 去手写 / 百度去水印 | 需模型 |
| 翻译 | 需第三方 API + 联网 |
| 爬虫类（网站图标下载、QQ 头像、公众号二维码） | 与离线办公工具定位不符 |
| 推文海报生成 | 复杂排版，前端更合适 |
| 服务端遍历目录类（本机文件搜索、目录列表、批量复制、随机抽文件） | **与「上传→临时目录→打包下载」安全模型冲突**（`system_file_search` 已因此移除） |
| 学习查询类（亲戚计算器、成语接龙、元素周期表…） | 需维护词库，与办公定位不符 |
| 文字隐写、任意体积文件生成、图片增加体积 | 无实用价值 |

## 8. 需要你拍板的 3 件事

1. **`document_convert` 聚合入口 vs 散落小工具** —— 我倾向聚合（一个入口 + 源/目标两个下拉，内部路由），用户只记一个地方，后续加格式不用新增工具位。
2. **`media` 音视频分类是否要做** —— 需要 ffmpeg 且大文件处理要上异步任务框架，成本高；我建议直接砍掉不做。
3. **`calc` 计算分类放工具箱里 vs 独立模块** —— 放工具箱里最省事（纯前端 `frontendOnly`，复用现有 tab 框架），但会让工具箱从「文件处理」变成「综合工具箱」，你接受这个定位变化吗？
